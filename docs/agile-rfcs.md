# Agile and RFC governance

The harness maps a task to an explicit sprint, backlog state or `not_applicable`. A Sprint Goal focuses work; the task briefing supplies scope and acceptance; evidence/checks/report support inspection. The report informs daily coordination and review but does not replace human discussion.

An RFC is a structured proposal for a systemic improvement. It records observation, reproduction, evidence, alternatives, risk, mitigation, evaluation and acceptance. An accepted RFC is not a release. A maintainer converts it into a decision record and implementation task when prioritized. Retrospective patterns may create RFC drafts; every task does not require one.
